Project Overview

This project aims to build a locally hosted, AI-assisted marking system for programming exams. Subject coordinators can manage workspaces and teams, create exams, import Canvas submissions, and configure question types and marking rubrics. Tutors can review individual or grouped responses, inspect automated test results and AI-suggested code corrections, and confirm rubric-based marks. Original submissions must remain unchanged, and final marks must always be confirmed by an authorised human marker

The system must identify and group identical short-answer responses together for short-answer questions.

The system must display an overview of all answer groups to the marker in a bar graph. Higher bar means more students in that group.

FR 4: AI-Assisted Function Marking

ID

	

Feature

	

Description

	

Priority / Note




FR4.1

	

Flagging

	

The system must detect submissions that fail to compile or run and forward them to a locally hosted LLM, Qwen2.5 coder 7B BF16, to generate a minimal fix.

	

Essential / High




FR4.2

	

Generate Minimum Fixes

	

The system must request local LLM to propose the minimum code modification required for the code to be compiled and run successfully. The system must then run the modified code against the same predefined tests and display the result to the tutor. This process should happen upon the creation of the exam. 

	

Essential / High




FR4.3

	

Present Changes

	

AI corrections must remain separate from the original submission. Tutors must be able to review the changes, compare available test evidence, and request regeneration without changing the original answer or automatically changing a confirmed mark.

	

Essential / High




FR4.4

	

Explain Changes

	

The system should display concise one-sentence explanations for suggested modifications.

	

Optional / Low




FR4.5

	

Re-running test cases

	

The system must show test case results of both the student's original code and  the AI-corrected code side by side. 

	

Essential / High




FR 4.6

	

Re-running AI suggestions

	

The system should allow the tutor to regenerate AI suggestions.

	

Optional / Medium




FR4.7

	

Human Approval

	

Only authorised human markers, including tutors and subject coordinators with marking permission, may confirm final marks.

	

Essential / High




FR4.8

	

Storing recommendations

	

AI suggestions and associated test results must be retained according to the agreed data-retention policy and linked to the relevant submission and review history.

	

Essential / High




FR4.9

	

Local LLM only

	

The LLM must be run locally. The system must not call third-party hosted AI services such as ChatGPT, Claude, Gemini, or other external AI APIs.

	

Essential / High



FR 5: Marking functions

ID

	

Feature

	

Description

	

Priority / Note




FR5.1

	

Interface

	

The system must provide a graphical interface for tutors and markers.

	

Essential / High




FR5.2

	

Question types

	

The system must support seven initial question types: 

Expression output

Single assignment statement

Multiple choice

Code completion

Debugging

Coding questions

Short answer 

	

Essential / High




FR5.3

	

Review

	

The system must provide a hierarchical review interface with three navigation levels. Level 1 lists all exam questions with marking progress. Selecting a question opens Level 2, listing that question's student answers (individually or grouped by identical/similar code) with mark status. Selecting an answer opens Level 3, which displays the question text, the student's submitted code, test case results for the original code, the AI-recommended correction as a minimal changeset with its own test case results, and the mark assigned to that answer. The marker must be able to navigate back up at any level.

	

Essential / High




FR5.4

	

Manual Marking

	

The system must allow tutor to manually mark at any point. All final marks should be decided by human marker. 

	

Essential / High




FR5.5

	

Rubric View

	

The system must display rubric options when tutors mark the exam 

	

Essential / High




FR5.6

	

Record Marking

	

The system must record and save all marking progress automatically for each student and question (so tutor can stop and resume). Saving the progress should not take longer than 1s.

	

Essential / High

2. Quality Requirements
QR 1: Security, Privacy & Compliance

ID

	

Feature Description

	

Priority / Note




QR1.1

	

The system must not send student submissions, student identifier, marks, rubric information, testing results to external third-party AI services. AI processing must be performed by the locally deployed model.

	

Essential / High




QR1.2

	

Production marking data must be stored on the authorised local host, such as the coordinator’s device or an approved local server. Authorised tutors access the shared marking workspace through a browser.

Within the application, marking data must only be accessible to authorised Tutor and Subject Coordinator.

	

Essential / High




QR1.3

	

The system must maintain an auditable history of marking decisions (who associated students and questions/when date and time of the change), including test results and AI suggestions.

	

Essential / High



QR 2: Reliability

ID

	

Feature Description

	

Priority / Note




QR2.1

	

The system should detect a CSV file that cannot be analyzed and or is missing the required columns, reject the import malformed or messy CSV data gracefully, including spacing, indentation, and formatting issues. (display the import error to the markers maybe)

	

Essential / High




QR2.2

	

The system must preserve marking progress between sessions. 

After a maker saves a marking progress and closes the application, the system must restore the saved marks, marking status, answer groups, test results, and recorded AI decisions when the same marking session is reopened.

	

Essential / High




QR2.3

	

The system must not automatically finalise a student's mark from test results or AI output where final marks are decided and confirmed by human tutors/markers.

	

Essential / High




QR2.4

	

Risk-averse grouping. The system must prioritise avoiding incorrect groupings over maximising efficiency. The answers that cannot be identified in the same group must remain separate and waiting for markers to review.

	

Essential / High




QR 2.5

	

The system must automatically back up all marking data at regular intervals while marking is in progress. Backups must include marking progress, final marks, comments, answer groups, test results, AI suggestions, and audit logs. 

The coordinator must be able to restore the system from a valid backup if the application crashes, the database becomes corrupted, or the server fails.

	

Essential / High

Feature Description

	

Priority / Note
